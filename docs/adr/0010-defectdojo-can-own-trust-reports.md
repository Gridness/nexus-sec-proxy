# DefectDojo can own Trust Reports

When the DefectDojo feature is compiled in and activated, one DefectDojo Test per enforced block is the authoritative Trust Report, with separate active and verified Findings for its block-relevant vulnerabilities; `report_only` decisions remain in existing audit and decision records. Tests preserve every block occurrence, while vulnerability Findings use stable repository, target, and vulnerability identities so repeated requests deduplicate as remediation work; the dedicated `Nexus Security Proxy Scan (Generic Findings Import)` Test Type must use DefectDojo's `Unique ID From Tool` deduplication algorithm. An unsupported-target block receives one informational Policy Finding instead of an empty Test. Every Test belongs to one pre-created Reporting Engagement identified by configuration; the proxy records repository, policy, and verified Nexus Requester context as report metadata instead of creating DefectDojo Products or Engagements or trusting client-asserted identity. Local and DefectDojo reports expose the same verified Requester and scanner-supported Mitigation content. The artifact response and any Security Notification link directly to the authoritative report, so viewing a DefectDojo-backed report is governed by DefectDojo authorization rather than bearer-link possession. DefectDojo owns report retention and deletion; the proxy receives no bulk-delete role. Local HTML report creation and serving are not used while DefectDojo is active, and a reporting failure keeps the artifact denied without producing a security notification. Builds without an active DefectDojo integration retain local Trust Reports, preserving a standalone deployment path while avoiding two competing records for the same block.
