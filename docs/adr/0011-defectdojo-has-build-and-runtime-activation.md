# DefectDojo has build-time and runtime activation

The standard binary and Docker image include the default `defectdojo` Cargo feature, which enables one concrete optional `nexus-sec-proxy-defectdojo` crate targeting DefectDojo Open Source 3.x API v2 capabilities; the integration does not introduce a generic reporting trait or sink framework or carry 2.x compatibility branches. A deployment uses DefectDojo only when `NEXUS_SEC_PROXY_DEFECTDOJO_ENABLED=true`; otherwise it retains local Trust Reports. Activation requires a valid HTTPS service URL, except that loopback HTTP is accepted for local testing. Featureless builds remain available for hardened deployments, and requesting runtime activation from a binary built without DefectDojo support fails startup instead of silently falling back.
